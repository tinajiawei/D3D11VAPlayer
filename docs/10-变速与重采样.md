# 10 变速与重采样：一次"×/÷"方向错误的全复盘

## 现象

用户报告：拉快速度，声音反而变慢；拉慢速度，声音反而变快。视频和进度条是对的，只有音频"反了"。

## 根因：重采样输出率公式方向写反

设备（声卡）每秒固定消费 D 个样本。设倍率为 S：

- 1 墙钟秒内要听到 S 秒内容；
- 这 S 秒内容对应 D 个设备样本；
- 所以**每秒内容应产出 D/S 个样本** → 输出率 = 设备采样率 ÷ S。

代码最初写成 `设备采样率 × S`：

- S=2 时输出 88200Hz，设备按 44100 消费 → 每秒只听 0.5 秒内容 → **变慢**；
- S=0.5 时输出 22050Hz → 每秒听 2 秒内容 → **变快**。

方向完全相反，而且这个错误从最初实现就存在，文档（03/06）也跟着写错了。

## 为什么主时钟是乘法而重采样是除法

主时钟算的是"内容时间"：`master = 设备已播秒数 × S`。设备走 1 墙钟秒，内容就过了 S 秒——所以主时钟用乘法。

重采样器算的是"产出率"：给设备喂样本的速度。设备消费率固定，倍率越高，每秒内容对应的样本越少——所以输出率用除法。

一句话：**时钟管"时间换算"，重采样管"样本换算"，两者方向相反。**

## 验证方法：测内容推进速率，而不是听

在音频解码线程写入时每秒打一条 pts（`[adec] 写入音频 pts=`），固定倍率保持 5 秒，看 pts 每墙钟秒前进多少：

| 倍率 | 重采样输出率 | 实测 pts 推进 |
| --- | --- | --- |
| 1.0x | 44100 Hz | +1.00 s/s |
| 2.0x | 22050 Hz | +2.02 s/s |
| 0.5x | 88200 Hz | +0.51 s/s |

## 本主题相关的其他坑

1. **重开失败必须重试**：`resampler_.open()` 返回值一度被忽略，失败后重采样器处于关闭态，convert 全部失败 → 无声。
2. **拖动去抖**：变速事件密集时每次重开都清空环形缓冲，声音被切断；加 80ms 去抖，停稳后重开一次。
3. **变速后要锚定主时钟**：重开窗口期（旧速率残音 + 静音）会让音频内容落后；冻结主时钟直到新倍率第一帧写入再锚定。
4. **坏 IAudioClock 会话禁用**：位置校验 + 推进速率校验（0.5x~1.5x），一旦异常本会话不再用硬件时钟，防止"看起来一致"的坏时钟把主时钟带慢。

## 进阶：time-stretch（变速不变调）

简单重采样变速会改变音调（2x 像"快进+变尖"）。真正"变速不变调"需要时间伸缩：libavfilter 的 `rubberband`/`atempo` 或 libmysofa 等。原理是分帧 + 交叠相加（OLA/WSOLA）或相位声码器（phase vocoder），代价是 CPU 与延迟。作为学习项目，这是"变速"章节的自然进阶题。
