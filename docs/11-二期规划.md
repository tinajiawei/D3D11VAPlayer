# 11 二期规划（动态壁纸 + 模块化）

> 本文是一期收官后的"设计稿"：定义 v0.2 的范围、里程碑、接口契约与验收标准。
> 一期 = 能播的引擎（docs/00–10）；二期 = 能当壁纸用的引擎 + 可插拔模块体系。

## 作用

回答三个问题：

1. 二期要做什么、按什么顺序做、为什么这个顺序？
2. 模块化做到什么程度（接口 → DLL → 注册表工厂）？
3. 每个里程碑怎么验收、踩过哪些坑？

## 二期目标

1. **壁纸体验**：控制面板浮到桌面（不再是壁纸窗口里看不见的面板），多显示器、托盘、自启、配置持久化。
2. **模块化**：接口先行，渲染/音频/同步/解码各自可替换，最终拆成独立 DLL（参考 RDCodec 的 `plugin\<ver>\*.dll` 模式）。
3. **新媒体源**：WebView2 网页壁纸，与视频/图片/GIF 并列。
4. **更多硬解后端**：AMF（AMD）/ QSV（Intel）/ NVDEC（NVIDIA），DecoderFactory 注册槽已留好。
5. **采集闭环**：WGC 屏幕采集 + WASAPI loopback 音频采集，复用解码→渲染管线。
6. **性能**：D3D11VA 显存帧直通渲染（省一次 GPU→CPU→GPU 拷贝）。

## 控制面板浮层（M2 当前实现）

### 为什么必须独立窗口

壁纸模式把视频窗口挂到桌面 WorkerW 之下（图标之下、背景之上）。控制面板如果画在同一个窗口里，就会跟着沉到图标下面——用户看不到，也点不到。所以面板必须是独立窗口。

### 实现要点

- **窗口**：无边框 `WS_POPUP` + `WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE`，默认停在工作区右上角，不抢焦点、不进任务栏。
- **渲染**：面板专用 ImGui context + 独立 DXGI flip-model 交换链；与主窗口共用同一个 D3D11 device/immediate context，但**串行**使用（都在引擎渲染线程，一帧内先画视频、再画面板）。
- **线程模型（本轮踩坑重点）**：创建/销毁/绘制全部在渲染线程执行；主线程只通过 `request_create` / `request_destroy` 发请求。最初实现让主线程直接销毁面板（ImGui_ImplDX11_Shutdown + 交换链释放），渲染线程同时还在用同一 immediate context 画主窗口 → 0xC0000005。教训：**D3D11 immediate context 与 ImGui context 都不是线程安全的，谁用谁销毁**。
- **面板消息**：面板窗口创建在渲染线程，它的 WndProc 消息也由渲染线程每帧 `PeekMessageW` 泵送，输入状态用原子变量传递。

### M2 后续

- 位置记忆（写入 ini）、半透明（需评估 flip-model 与 layered 的兼容性，或改用 DWM）
- 多显示器：面板跟随当前显示器；每屏独立壁纸渲染实例
- 托盘图标（隐藏面板/切换壁纸/退出）、开机自启
- 壁纸模式异常退出后的恢复（进程重启自动重新挂载）

## 模块化接口契约

| 模块 | 接口 | 一期实现 | 桩实现 | 替换方式 |
| --- | --- | --- | --- | --- |
| 渲染 | `IRenderer`（src/api/irenderer.h） | D3D11Renderer | HeadlessRenderer | `me_create_player_ex(..., ME_PLAYER_FLAG_HEADLESS)` |
| 音频 | `IAudioSink`（src/api/iaudio_sink.h） | AudioOutput（WASAPI） | NullAudioSink | `MediaPlayer::set_audio_sink`（C API 用 NULL_AUDIO flag） |
| 同步 | `ISyncEngine`（src/api/isync_engine.h） | SyncEngine（音频主时钟） | （SyncEngine 无音频时已回退单调时钟） | `MediaPlayer::sync_` 注入 |
| 解码 | `IDecoder`（src/media/decoder.h） | sw / d3d11va 插件 DLL | — | `plugin\<ver>\*.dll` 注册表 |

M3 的目标：前三行从"接口 + 同进程实现"升级为"接口 + 独立 DLL"。每个 DLL 导出工厂函数（`extern "C"`），`media_engine` 只保留编排（MediaPlayer/SyncEngine 调度 + C API）。

### DLL 化的 ABI 注意点

- 纯虚接口 + 工厂函数是 ABI 边界；新增虚函数 = 破坏 ABI，必须升版本目录 `plugin\2\`。
- 头文件改动后必须 `cmake --build build --clean-first`（本项目多次复现过 ABI 错位导致的 0xC0000005）。
- 跨 DLL 传递对象：所有权用 `std::unique_ptr` + 工厂返回裸指针，销毁走同一 DLL 的释放函数，避免 CRT 堆不一致。

## 验收标准

- **M1**：`media_engine_tests.exe` 含桩用例；`--headless --run-seconds 6` 输出 `draw>0 present>0` 且 0 退出码。
- **M2**：`--wallpaper` 自动测试 10 秒内进入/退出无崩溃；退出后无新增 Application Error 事件；面板可点击（进度条/速度/音量/壁纸按钮）。
- **M3**：删除任一模块 DLL 后引擎启动报"缺后端"而不是崩溃；`plugin\2\` 与 `plugin\1\` 可并存。
- **M4**：WebView2 页面作为壁纸渲染，视频/图片/网页可同屏切换。
- **M5**：AMD 机器上 AMF 硬解 HEVC/H.264，解码器报告 `amf`，失败自动降级软解。
- **M6**：采集桌面 30 秒，输出与源分辨率一致的流畅画面；loopback 音频与画面同步容差 ±40ms。
- **M7**：D3D11VA 直通路径 CPU 占用显著下降；进程崩溃后 5 秒内壁纸自动恢复。

## 风险与学习点

1. **D3D11 多线程**：immediate context 非线程安全；多窗口方案要"一线程管到底"或 deferred context。
2. **z-order 因系统而异**：Win10/11 的 WorkerW/SHELLDLL_DefView 行为有差异，壁纸挂载要保留探测与失败提示。
3. **WebView2 与 D3D11 共享**：WebView2 有自己的渲染进程，叠加/共享纹理是技术难点。
4. **DLL 化后的调试**：符号、堆、接口版本都要跟着 `plugin\<ver>` 走，改接口要当"新协议"对待。
5. 每个里程碑完成后：更新 docs/00 模块地图、docs/09 阅读地图、README，再提交（本项目文档同步规则）。
