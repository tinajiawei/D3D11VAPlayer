# 04 解码器抽象：可插拔的软解/硬解

> 本篇讲项目最核心的抽象：为什么上层只认识 `IDecoder`，软解/硬解如何像插头一样即插即用。

## 1. 作用

把"从一个包变成一帧"这件事抽象成一个接口，让播放器主体对**解码方式**（软件 CPU 解码 / D3D11VA 硬件解码 / 未来的 AMF、QSV、NVDEC）完全无感。

## 2. 接口设计

```cpp
class IDecoder {
public:
    virtual ~IDecoder() = default;

    // 用流参数（分辨率/编码/像素格式）初始化解码器
    virtual Error open(const AVCodecParameters& params) = 0;

    // 喂一个压缩包；nullptr 表示"流结束了，把缓冲的帧都吐出来"
    virtual void push(AVPacket* pkt) = 0;

    // 取一帧解码结果
    //   返回 Ok           ：frame 有效，可渲染/播放
    //   返回 NeedMoreData  ：请继续 push，解码器要更多输入
    //   返回 Eof           ：已冲刷完毕，不再有帧
    virtual PopResult pop(AVFrame* frame) = 0;

    // 重置解码器内部状态（seek 时清掉 B 帧重排缓冲）
    virtual Error flush() = 0;

    virtual void close() = 0;
    virtual const char* name() const = 0;   // "sw" / "d3d11va" / "amf" ...
    virtual bool is_hardware() const { return false; }
};
```

### 为什么是"push 一包 / pop 一帧"而不是直接返回一帧

现代解码器（AVCodec 也是）是**有状态管道**：喂一包可能出 0 帧（比如只凑齐了参考帧），也可能出多帧（flush 时把缓冲全吐出来）。把接口设计成显式的 push/pop 握手，正是把 FFmpeg 的 `avcodec_send_packet` / `avcodec_receive_frame` 语义原样搬进自己的抽象里。

## 3. 软解实现（SwDecoder）

```cpp
Error SwDecoder::open(const AVCodecParameters& p) {
    codec_ = avcodec_find_decoder(p.codec_id);
    ctx_   = avcodec_alloc_context3(codec_);
    avcodec_parameters_to_context(ctx_, &p);
    return wrap_av(avcodec_open2(ctx_, codec_, nullptr));
}

PopResult SwDecoder::pop(AVFrame* out) {
    // 先把手上攒着的包送进去
    if (pending_pkt_) {
        int r = avcodec_send_packet(ctx_, pending_pkt_);
        pending_pkt_ = nullptr;
        if (r < 0 && r != AVERROR(EAGAIN)) return error(...);
    }
    int r = avcodec_receive_frame(ctx_, out);
    if (r == AVERROR(EAGAIN)) return NeedMoreData;   // 要更多包
    if (r == AVERROR_EOF)    return Eof;
    return Ok;
}
```

注意 `avcodec_send_packet` 可能返回 `EAGAIN`（内部缓冲满），此时**包还没被收下**，实现里要保留 pending 包下次再送——这是新手最容易漏的状态机细节。

## 4. 硬解如何插拔（D3D11VA）

### 原理一句话

解码计算从 CPU 挪到 GPU，FFmpeg 通过 `AV_HWDEVICE_TYPE_D3D11VA` 访问显卡的解码单元（AMD/NVIDIA/Intel 通用）。

### 硬解解码器的不同点

```cpp
Error D3D11vaDecoder::open(const AVCodecParameters& p) {
    // 1. 创建 GPU 设备上下文
    av_hwdevice_ctx_create(&hw_ctx_, AV_HWDEVICE_TYPE_D3D11VA, nullptr, nullptr, 0);
    // 2. 打开解码器时挂上硬件上下文
    codec_ctx_->hw_device_ctx = av_buffer_ref(hw_ctx_);
    avcodec_open2(codec_ctx_, codec_, nullptr);
    // 3. 校验解码器确实接受了硬解（输出像素格式变成 D3D11 纹理）
    if (codec_ctx_->hw_pix_fmt != AV_PIX_FMT_D3D11) 硬解不可用 → 抛给上层降级;
}
```

### 帧怎么回到渲染器

硬解出来的 `AVFrame` 数据在**显存纹理**里，不能被 CPU 直接读。本项目一期用 `av_hwframe_transfer_data` 拷回 CPU 侧 NV12，走与软解完全相同的渲染路径（代价是一次显存→内存拷贝）。

> 真实产品为省这次拷贝，会让渲染器直接消费 D3D11 纹理（GPU 全链路）。一期选择"统一渲染路径 + 拷贝"是为了把架构风险先隔离，文档 06 的进阶路线里列出了 GPU 直通改造。

## 5. DecoderFactory：注册表

```cpp
class DecoderFactory {
public:
    using Creator = std::function<std::unique_ptr<IDecoder>()>;

    static void register_backend(std::string_view name, Creator creator);

    // 按优先级尝试，直到成功；全部失败返回 nullptr
    static std::unique_ptr<IDecoder> create(const AVCodecParameters& p, bool prefer_hw);
};
```

注册：

```cpp
DecoderFactory::register_backend("sw", [] { return std::make_unique<SwDecoder>(); });
DecoderFactory::register_backend("d3d11va", [] { return std::make_unique<D3D11vaDecoder>(); });
// 未来：register_backend("amf", ...); register_backend("qsv", ...); register_backend("nvenc", ...);
```

播放器只写：

```cpp
decoder_ = DecoderFactory::create(*params, prefer_hw_);
```

新增一种硬解后端 = 实现一个类 + 注册一行。**上层零改动**。

## 6. 反例对比：不抽象会怎样

```cpp
// 假设没有 IDecoder
if (use_hw) { d3d11va_open(...); d3d11va_decode(...); }
else        { sw_open(...);      sw_decode(...); }
// 播放器、seek、帧队列、渲染到处都要判断分支
// 加 AMF 时：全项目每个调用点再插一个 if
```

结果：解码方式的选择渗透进所有模块，改一处漏一处，测试翻倍。抽象把"选哪种解码"收敛到**一个工厂调用**。

## 7. 边界条件与降级

- 编码格式 GPU 不支持（如 AV1 老显卡、少见 profile）→ `open` 失败 → 工厂自动降级软解；
- 硬解上下文创建失败（驱动问题）→ 同上；
- 解码器 open 成功但运行时持续出错 → 记错误日志，播放器按"解码失败"处理，不静默硬撑；
- 软解兜底必须永远可用：这是整个系统的最后防线。

## 8. 验收标准（本模块）

- 软解：H.264/HEVC/AV1 视频、AAC/MP3 音频、PNG/JPEG/GIF/WebP 图片全部可解码；
- 硬解：H.264/HEVC 走 D3D11VA，控制面板能显示当前后端名；
- 切换：同一文件软/硬解可一键切换，帧不花、声不断。
