# 12 项目发展规划（v0.3+）

> 回答一个问题：现在的 MediaEngine "能跑"，但离"可靠、好用、可分发"还差什么，按什么顺序补。

## 现状评估（诚实的粗糙点）

1. **配置零散**：音量/速度/设备/URL/面板位置散落各处，没有统一配置文件，重启不记忆（面板位置除外）。
2. **日志粗糙**：大量 fprintf 直出，无日志文件、无级别统一、无滚动；中文编码在部分环境乱码。
3. **错误处理不完整**：部分失败路径只打日志不恢复；音频设备热插拔、解码器异常、渲染器丢失等边界未全覆盖。
4. **画质停留在 8bit**：10bit HEVC 靠 swscale 降级显示，无 HDR/10bit 直出；硬解帧仍走 CPU 拷贝（GPU 直通未做）。
5. **壁纸不完整**：单显示器；网页壁纸无导航控制（后退/刷新在代码层，面板没有）；部分网站（如百度反爬）加载失败没有用户提示。
6. **采集是演示级**：屏幕/音频采集能跑，但未接入播放管线闭环。
7. **测试是黑盒冒烟**：29 场景验收有用但无 CI、无单元测试覆盖同步/队列边界、无 UI 自动化。
8. **发布靠手动**：每次手动打包 zip + push；无安装器、无自动更新、无崩溃转储。
9. **性能未量化**：无统一性能面板，丢帧/内存/解码耗时只有日志。

## 规划原则

按"**可靠 → 好用 → 画质 → 可分发**"的顺序推进；每一阶段保持"改完即验、文档同步、版本发布"的节奏。

## 阶段一：工程化补课（v0.3.x）

目标：把"能跑"变成"可靠、可维护、可自动化验证"。

- 统一配置：`config.ini`（音量/速度/默认设备/URL/硬解偏好/面板位置/壁纸选项），启动读取、退出保存。
- 日志系统：写入 `logs/media_engine.log`（按天滚动、大小上限），级别可配置；把现有散落 fprintf 归拢；移除调试期临时日志。
- 错误与恢复：open 失败分类与用户提示；音频设备热插拔重建；解码器重建策略固化（已有基础，补测试）；渲染器设备丢失恢复。
- 测试强化：单元测试覆盖队列/时钟/同步/解码重建/配置读写；验收脚本纳入 CI。
- CI：GitHub Actions —— 构建 + 单元测试 + 打包 zip 到 Release；每次推送自动产出可下载包。
- 代码清理：统一命名/注释风格，删除死代码与临时文件，头文件依赖最小化。

验收：新电脑克隆仓库 → 一条命令构建 → 全量测试通过 → 自动产出发布包。

## 阶段二：壁纸体验完善（v0.4.x）

目标：壁纸真正"日常可用"。

- 多显示器：每屏独立壁纸实例（视频/网页）。
- 网页壁纸控制：面板加后退/前进/刷新/加载状态；URL 白名单与弹窗策略；导航失败的用户提示（替代控制台日志）。
- 托盘完善：最近打开文件、开机自启、静音快捷。
- 播放列表/轮播：壁纸多文件循环，间隔可配（基础版序列播放已在 v0.2.9 提前落地：文件夹递归扫描 + 上/下一个 + 自动播放下一个）。
- 壁纸模式性能：隐藏控制面板时暂停无关渲染/解码开销。

验收：双显示器同时铺满；网页壁纸可全程鼠标/托盘控制；轮播 8 小时无崩溃。

## 阶段三：性能与画质（v0.5.x）

目标：从"能播"到"播得好"。

- GPU 直通：D3D11VA/AMF 纹理直接进渲染器（docs/11 已有设计稿），省 CPU 拷贝。
- 10bit/HDR 直出：P010 不再 swscale 降级；着色器支持 10bit 采样。
- 音频变速不变调（time-stretch，libavfilter/rubberband 方案）。
- 性能面板：帧率/丢帧/解码耗时/内存占用可视化。

验收：硬解 1080p HEVC 10bit 播放时 CPU 占用显著下降；4x 变速声音可懂。

## 阶段四：产品化（v0.6+）

目标：别人拿到就能装、能用、能升级。

- 安装器（Inno Setup 或 MSIX）：开始菜单/桌面快捷方式、卸载、可选开机自启。
- 自动更新：启动时检查 GitHub Releases，下载并替换（或提示）。
- 崩溃转储：minidump 本地保存 + 可选上报；符号文件随发布包。
- 皮肤/主题与面板布局持久化。
- 采集闭环：屏幕采集作为壁纸源（WGC 替换 DXGI）、loopback 音频接入输出。

## 长期方向（学习向扩展）

- 流媒体：MediaSource 支持 http(s)/HLS，边下边播。
- 滤镜链：解码与渲染之间插入缩放/模糊/叠加等 IFilter。
- 字幕渲染（libass）。
- 平台扩展（Linux/Wayland 壁纸）——学习价值高但非当前目标。

## 版本节奏建议

- 每个阶段 1-2 周，小步提交、随时可发布。
- 版本号：v0.3.x 阶段一，v0.4.x 阶段二，依次类推；每次发布更新 CHANGELOG + 打 tag + 重建 zip。

## 下一个立即动手项（建议）

1. 配置系统（config.ini）——影响面小、收益大，几乎所有粗糙体验都与此相关。
2. 日志收拢到文件——排查问题从"翻控制台"变"看日志目录"。
3. CI + 自动打包——发布从"手动"变"一键"。
