# 06 调试与排障

> 学习项目最值钱的不是"能跑"，而是"出问题知道怎么查"。本篇先给方法论，再给本项目一次真实崩溃的完整排查过程。

## 1. 作用

建立一套可复用的排障流程，覆盖四类典型问题：

- 崩溃（access violation / 异常退出）
- 死锁（程序挂起）
- 音画不同步
- 卡顿/掉帧

## 2. 排障工具箱

| 工具/手段 | 用途 | 本项目里怎么用 |
| --- | --- | --- |
| 日志 | 定位"走到哪一步" | `ME_LOG_*`，每线程启动/结束都有日志 |
| WER 报告 | 崩溃后自动留下证据 | `C:\ProgramData\...\WER\ReportArchive` 的 Report.wer |
| dumpbin | 查 DLL 导出、反汇编 | 把崩溃偏移映射成函数 |
| 二分输入 | 隔离模块 | 纯视频/纯音频/图片分别测 |
| 文件重定向 | 看挂起程序的输出 | stderr 无缓冲，重定向到文件 |
| 单元测试 | 隔离数据结构 bug | 队列/时钟/环形缓冲用例 |

## 3. 崩溃排查流程

### 第 1 步：先复现，再缩小

用**最小复现输入**代替真实文件：

- 只崩音频 → 用 wav；
- 只崩视频 → 用无音轨 mp4；
- 图片、GIF 单独测。

本项目靠这个一步锁定了"问题在音频路径，不在视频/渲染/窗口"。

### 第 2 步：读崩溃报告

`Report.wer` 给出三个关键字段：

- 故障模块（哪个 DLL）；
- 异常代码（0xc0000005 = 访问违例，0xc0000409 = 栈损坏/fast-fail）；
- 错误偏移（模块内偏移）。

### 第 3 步：把偏移映射成函数

```
dumpbin /exports C:\WINDOWS\System32\ucrtbase.dll   # 导出表
dumpbin /disasm  C:\WINDOWS\System32\ucrtbase.dll   # 非导出代码反汇编
```

本项目崩溃偏移 0x25f31 不在导出表里，反汇编后看到 0x7EFEFEFEFEFEFEFF 魔法数 + 逐 8 字节扫描——典型的 **strlen 内联实现**。于是怀疑方向变成"谁在传 NULL 字符串"。

### 第 4 步：反向找调用点

strlen 崩溃 → 找最近的字符串日志 → `av_get_pix_fmt_name` 在音频上下文返回 NULL。修复：判空后再进日志。

**复盘**：如果没有日志，这轮排查会慢十倍。日志是排障的第一生产力。

## 4. 死锁排查

症状：程序挂起，CPU 占用低（0% 左右）。

### 判定

- 挂起 + 低 CPU = 等锁/等条件变量（死锁或活锁）；
- 挂起 + 高 CPU = 死循环（如并发测试的无限 pop）。

### 本项目的高频死锁点

1. **abort 忘了 notify_all**：pop 永远沉睡；
2. **先 join 后 abort**：join 等一个永远醒不来的线程；
3. **无符号下溢把循环条件搞成永真**（05 篇坑 2）。

### 定位手段

- 每个线程入口/出口打日志，看"最后一个打印在哪"；
- 给测试加进度标记（writer/reader 各自打印），看卡在哪一侧；
- 用文件重定向避免管道缓冲吞输出。

## 5. 音画不同步排查

### 判定基准

本项目容差 ±40ms。人耳对音频抖动敏感，人眼对视频宽松，所以视频去追音频。

### 排查路径

1. 确认主时钟来源：面板/日志看是不是音频时钟在工作（`IAudioClock` 位置）；
2. 确认 pts 换算：`frame->pts * av_q2d(stream->time_base)`，别把流时间基和 AV_TIME_BASE 混用；
3. 确认 seek 顺序：队列 flush → 解码器 flush → 源跳转 → 时钟复位（03 篇第 5 节）；
4. 确认丢帧阈值：落后 40ms 才丢，阈值太小会糊。

## 6. 卡顿/掉帧排查

### 先量化，再定位

- 面板显示"丢帧计数"；
- 在解码循环和渲染循环各加计数器，对比"解码帧数 vs 上屏帧数"；
- 看 CPU 占用：软解 1080p 在慢 CPU 上就是会掉帧，这不是 bug 是算力。

### 常见原因与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 解码慢导致画面顿 | 软解吃 CPU | 换硬解；降低分辨率 |
| 慢盘读取卡住 | 无缓冲 | 包队列上限加大 |
| 音画都卡但 CPU 低 | 队列背压传导 | 检查最慢环节（可能是音频设备） |
| 掉帧但流畅 | 丢帧策略生效 | 正常，说明在追音频 |

## 7. 排查方法论总结

1. **可复现的输入**：造最小样例；
2. **日志分段**：关键路径每步一行；
3. **二分**：视频/音频/图片分开测；
4. **证据链**：WER + dumpbin + 反汇编，不猜；
5. **修完写进文档**：把这次教训写进 05 篇踩坑实录，下次不再踩。

## 8. 设备/环境类问题：默认音频端点失效（AUDCLNT_E_DEVICE_INVALIDATED）

**现象**：音频设备明明存在（`Get-CimInstance Win32_SoundDevice` 能看到声卡，`Audiosrv` 服务运行中），但 `IAudioClient::Initialize` 始终返回 `0x88890008`。

**根因**：`GetDefaultAudioEndpoint` 返回的"默认端点"可能是虚拟/远程音频设备（远程桌面、虚拟声卡、耳机驱动等），它对 `Initialize` 一直报"设备已失效"。这不是"没有设备"，而是**默认端点不可用**。

**排查路径**：

1. 先别信"没设备"的结论——查音频服务状态和声卡列表，排除环境误判；
2. 让失败信息带上 HRESULT（本项目统一用 `hr_hex` 输出），`0x88890008 = AUDCLNT_E_DEVICE_INVALIDATED`；
3. 枚举所有活动端点（`EnumAudioEndpoints(eRender, DEVICE_STATE_ACTIVE)`），逐个尝试初始化，跳过失效端点；
4. 事件驱动模式（EVENTCALLBACK）失败时回退普通轮询模式，兼容不支持低延迟模式的虚拟设备；
5. 全部失败才降级静音，并保留日志供排查。

**教训**：默认端点 ≠ 可用端点。凡依赖"系统默认设备"的代码都要有"枚举兜底 + 重试"的容错设计；错误码必须打全，否则一句话错误信息会把排查引向错误方向——本例就曾被误判成"这台机器没有声卡"。

## 9. 本项目的最后三坑（真实案例）

### 坑 A：条件变量缺通知 → 解码线程永久沉睡（播放器"只播 8 帧"）

**现象**：视频只渲染前 2-3 帧后定格，音频继续；日志显示渲染线程在空队列空转，解码线程既不结束也不产帧。

**根因**：`FrameQueue::push` 在队列满时用条件变量等待，但 `pop_front` 腾出空间后**没有 `notify_one`**。解码线程塞满 8 帧后沉睡，渲染线程取走全部帧后没有任何人唤醒它——典型的"生产者等空间、消费者忘记通知"死锁。包队列当初写对了，帧队列漏了。

**修复**：`pop_front` 末尾补 `cv_.notify_one()`，并新增并发回归测试（生产者塞满后阻塞，消费者取走，断言生产者最终完成）。此 bug 会让任何基于"有界队列 + 条件变量"的系统只跑一个队列深度的量。

### 坑 B：D3D11 默认背面剔除 → 全屏三角形被裁掉（黑屏但面板正常）

**现象**：窗口全黑，只有 ImGui 面板可见；纹理上传正常（读回验证有数据）、Draw 已执行。

**根因**：默认光栅化状态 `D3D11_CULL_BACK`，全屏三角形的绕序被判为背面，整个三角形被剔除。

**修复**：创建 `D3D11_CULL_NONE` 光栅化状态并绑定。**排查手法**：GPU 侧问题用"读回渲染目标"验证——Y 纹理有数据但 RTV 全黑，即可锁定绘制阶段。

### 坑 C：头文件布局变更后必须全量重建

**现象**：某次修改后随机访问违例，崩溃点在面板读取播放器成员（偏移错位）。

**根因**：给类加了新成员（`last_frame_`、`rasterizer_`）改变布局，增量构建留下按旧头文件编译的目标文件，同一对象在不同编译单元里成员偏移不一致。

**修复**：`cmake --build --clean-first` 全量重建后 5/5 稳定。**教训**：改头文件布局后不要相信增量构建的依赖追踪，特别是经历过多次手动编辑的文件。
## 10. 无声音与画面方向（第二轮实战）

### 坑 E：音频"瞬间灌完就静音"

**现象**：视频正常播放但没有声音。日志显示音频解码线程启动后立刻结束，帧计数只走了约 1 秒。

**根因**：环形缓冲的写操作是"丢弃最旧"模式，解码线程比声卡快得多，把整段音频瞬间灌进去（只留最后 0.8 秒），播完就静音。**生产者与消费者节奏脱钩**。

**修复**：生产者改用阻塞写（`push_blocking`，等空间再写），让解码节奏跟随声卡消费——和视频帧队列的背压同理；并加 `abort()` 防止关闭时 join 卡死。

### 坑 F：全屏三角形 UV 忘翻转 → 画面上下颠倒

**现象**：视频内容上下颠倒（旋转 90 的测试源看起来更乱）。

**根因**：D3D 屏幕底部是 clip y=-1，而纹理顶行是 v=0；顶点着色器直接 `uv = xy` 会把纹理顶行画到屏幕底边。

**修复**：`o.uv = float2(xy.x, 1.0 - xy.y)`。这是全屏三角形的经典坑，与背面剔除（坑 B）并列。

### 坑 G：FFmpeg 8 的旋转元数据在"帧侧数据"里

**现象**：检测不到旋转（日志无输出）。`av_stream_get_side_data` 在 FFmpeg 8 已删除，流上也没有 side_data 字段；包侧数据为空。

**根因**：FFmpeg 8 把显示矩阵挂到**解码后的帧**（`AV_FRAME_DATA_DISPLAYMATRIX`）。

**修复**：打开解码器后探测首帧的侧数据；探测循环里**解码器返回 NeedMoreData 时必须跳出取下一个包**（曾写成继续重试导致死循环卡死 open()）。

### 坑 H：中文路径 fopen 打不开

**现象**：F12 导出画面时文件没生成，无任何报错。

**根因**：`fopen` 用 ANSI 代码页解释路径，UTF-8 中文路径在 GBK 系统上失败。

**修复**：`MultiByteToWideChar` 转宽字符后 `_wfopen_s`。
## 11. 变速与 seek（第三轮实战）

### 坑 I：有音频时变速完全不生效

**现象**：面板/快捷键调速度，画面速度不变，音画脱节。

**根因**：`set_speed` 只改了回退时钟（PlaybackClock）的倍率，而**有音频时主时钟直接用音频硬件位置（1x）**，完全绕过了倍率。音频内容其实已变速（重采样器按"设备采样率 ÷ 倍率"输出），视频还在按 1x 追 → diff 持续漂移，画面卡死。

**修复**：主时钟 = `音频硬件位置 × 播放倍率`（2x 时设备走 1 秒=内容已播 2 秒）；变速瞬间重算 offset 保持时钟连续；渲染等待用**墙钟时间 = 内容时间 ÷ 倍率**。

### 坑 J：seek 后旧帧污染主时钟

**现象**：第一次跳转正常，之后位置错乱、画面巨卡（diff 达 +6 秒）。

**根因**：seek 只清空队列，但**解码线程可能正在解码旧包**（flush 前已取出的包），把 seek 前的旧帧推入已清空的队列；渲染线程拿到旧帧且"首帧对齐"再次触发，把主时钟错位到旧位置。

**修复**（三重防护）：
1. 解码线程内层循环在 `flush_requested_` 置位时停止推帧；
2. "首帧对齐"只在**首次播放**执行，seek 后主时钟由 seek 目标直接设定；
3. 渲染循环 pop 后与绘制前各查一次 seek 代次，旧帧直接丢弃。
## 12. 音频设备选择与 seek 卡死（第四轮实战）

### 坑 K：声音输出到了"显示器 HDMI"而不是用户扬声器

**现象**：用户拖入视频没声音。日志显示最终选中的设备是 "3 - 27G2G4 (AMD High Definition Audio Device)"——显示器音频口，用户 PC 默认扬声器是"天猫精灵 BOOM"蓝牙音箱。

**根因**：早期版本"枚举所有端点、第一个能初始化的就用"——默认设备（蓝牙音箱）初始化报 0x88890008 失败后，程序自动切到显示器音频，声音出在没人听的地方。

**修复**：
1. **默认设备优先**（用户系统设置里的扬声器），失败才枚举兜底；
2. 日志输出实际使用的设备名（`PKEY_Device_FriendlyName`）；
3. 控制面板新增"输出设备"下拉框，用户可手动切换扬声器（`AudioOutput::switch_device` 保留播放位置）。

### 坑 L：快进后画面完全不动（解封装线程"读完全文件就退出"）

**现象**：seek 后画面卡死，日志显示 seek 后 DRAW=0。第二次 seek 才出现——第一次能恢复是因为解封装线程当时还活着。

**根因**：本地文件读取极快，**解封装线程在播放开始后 1-2 秒就读完整个文件并退出**。seek 只移动了源位置，但没人再读包 → 没有新帧 → 画面定格。

**修复**：三个工作线程（解封装/视频解码/音频解码）在 EOF 后**挂起等待 seek 唤醒**而不是退出；seek 时 `notify_all` 并用 seek 代次（`seek_gen_`）作为唤醒条件；close 时也唤醒避免 join 卡死。

### 坑 M：seek 与读取并发操作同一 FFmpeg 上下文

**现象**：seek 偶发导致读取线程读到中间状态/卡住。

**根因**：`av_read_frame` 与 `avformat_seek_file` 并发访问同一 `AVFormatContext`（非线程安全）。

**修复**：`MediaSource` 内部 `io_mutex_` 串行化读包与 seek。
## 13. 竖屏拉伸与设备切换崩溃（第五轮实战）

### 坑 N：竖屏视频被拉伸

**现象**：手机竖拍视频（旋转 90° 后）被强行拉伸到横屏窗口，比例严重变形。

**根因**：渲染器把帧画满整个窗口，没有按内容宽高比适配。

**修复**：绘制前计算 letterbox 矩形（内容等比居中，旋转 90/270 时宽高互换），用视口裁剪，黑边清屏。

### 坑 O：面板枚举音频设备导致无音轨文件崩溃

**现象**：打开无音频视频（如 GIF、纯视频）立即崩溃，偏移在 IMMDeviceEnumerator::EnumAudioEndpoints（vtable 0x18）。

**根因**：面板新增"输出设备"下拉框**无条件调用** `audio_devices()`，而无音轨文件从未初始化音频枚举器，`enumerator_` 为空指针。

**修复**：设备枚举/切换入口判空，无音频时返回空列表。**教训**：新增 UI 查询接口时要考虑"该模块从未初始化"的状态。
## 14. 重新打开视频卡死（第六轮实战）

**现象**：播放一个视频后再打开另一个，画面卡死（open 阻塞）。

**根因**：close() 停线程时有两个"等待中的线程"没人唤醒：
1. **EOF 挂起线程**：解封装/解码线程在文件播完后挂起等待 seek，close 时没有 `media_cv_.notify_all()`，join 永远等不到；
2. **音频解码线程**：阻塞在环形缓冲 `push_blocking`（等声卡消费腾空间），close 时没有 `audio_.abort_ring()`，join 卡死。

**修复**：close() 里先 `media_cv_.notify_all()` + `audio_.abort_ring()` 再 join。

**教训**：任何"让线程等待"的机制，都必须在**所有退出路径**（seek 唤醒、close 唤醒、错误退出）配齐唤醒；遗漏的唤醒表现为"偶发卡死"，极难排查。
## 15. 线程唤醒/退出与缓冲排空专项审计（第七轮实战）

这一轮把所有 wait/notify/abort 点重新过了一遍，重点找"线程睡下去之后还有没有人负责叫醒它"。结论：大部分挂起都配了条件变量谓词（不会丢唤醒），但存在六处"叫醒路径缺失/被竞争吃掉/只写在文档里"的问题，本轮全部修复。

### 坑 P：seek 后 EOF 挂起线程没被唤醒（最高频）
**现象**：文件播放到结尾（ended 状态）后再拖动进度条/快进，画面永远不动。
**根因**：三个工作线程（解封装/视频解码/音频解码）在 EOF 后挂起等待 seek 代数变化，谓词本身正确，但 `seek()` 里**只改了代数、没有 `media_cv_.notify_all()`**。没有通知，等待线程永远醒不来；12 节坑 L 文档写了"seek 时 notify_all"，代码却在某轮改动里丢了。
**修复**：`seek()` 在 `seek_gen_.fetch_add(1)` 后补 `media_cv_.notify_all()`。
**教训**：改共享状态 + 条件变量唤醒必须写在同一处；文档描述的修复必须能在代码里搜到。

### 坑 Q：共享 flush 标志被两个解码线程竞争
**现象**：seek 后偶发开头残留旧音频/旧画面。
**根因**：`flush_requested_` 是单个 bool，视频/音频解码线程都用 `exchange(false)` 消费；谁先跑谁拿走，另一个线程的 `decoder->flush()` 和音频重采样器重开被跳过，解码器内部延迟帧混入 seek 后的新数据。
**修复**：拆成 `video_flush_requested_` / `audio_flush_requested_` 两个标志，各自消费。
**教训**：一个"请求位"只能有一个消费者；多消费者要么各配一个，要么用代数。

### 坑 R：io_mutex_ 声明了但从未加锁
**现象**：快速连续 seek 偶发卡死/读包错乱（12 节坑 M 号称已修）。
**根因**：`MediaSource` 头文件定义了 `io_mutex_`，注释也写了"av_read_frame 与 seek 不能并发"，但 `read_packet()` / `seek()` 实现里没有 `lock_guard`，等于没修。
**修复**：两个函数入口补 `std::lock_guard<std::mutex> lock(io_mutex_)`。
**教训**：审查"修复"要看实现，不能只信文档和注释。

### 坑 S：audio_done_ 复位顺序错误
**现象**：有音轨但音频输出全部失败（静音播放）时，视频播完永远不进入 ended，画面定格。
**根因**：`open()` 先按 `!audio_enabled_` 置 `audio_done_=true`，随后统一复位又写回 false，"无音频已完成"语义被覆盖。
**修复**：先复位所有 done 标志，再按 `!audio_enabled_` 置位。

### 坑 T：did_first_align_ 未在 open() 复位
**现象**：第二次打开文件后开头可能丢帧/短暂等待。
**根因**：首帧对齐只在首次播放执行，重新 open 后没有复位，第二个文件永远跳过对齐。
**修复**：`open()` 里 `did_first_align_ = false`。

### 坑 U：设备切换时环形缓冲指针竞争
**现象**：播放中切换扬声器偶发崩溃/无声音。
**根因**：`AudioOutput::ring_` 是 unique_ptr，`switch_device()` 里 abort 后 reset 替换对象，而音频解码线程可能正阻塞在旧对象的 `push_blocking` 上——跨线程读写 unique_ptr 是数据竞争，旧对象可能在等待者返回前析构（use-after-free）。
**修复**：`ring_` 改为 `std::atomic<std::shared_ptr<RingBuffer<float>>>`，写/清/abort 都先 `load()` 持有共享所有权，旧对象由最后一个持有者安全析构。

### 坑 V：push_blocking 单块大于容量会永久等待
**现象**：高倍速 + 大音频帧 + 多声道时理论可死锁（当前 0.2s 缓冲下接近临界）。
**根因**：旧实现等待"剩余空间 >= 整块 n"，若 n > 容量，条件永远不成立。
**修复**：改为分块写入（有空槽就写一段），保留 >16MB 防御丢弃；新增回归测试。

### 坑 W：解封装读包失败不推 EOF 哨兵
**现象**：文件读到一半损坏时，音/视频解码线程永远阻塞在 pop，不结束也不报错。
**修复**：`demux_loop` 错误分支先向两条包队列推 nullptr 哨兵再退出。

### 坑 X：暂停状态下 seek 后黑屏
**修复**：渲染线程暂停分支在 `last_frame_` 为空时从帧队列取一帧预览（校验 seek 代数）。

### 坑 Y：--debug 被当作媒体路径
**现象**：命令行带 `--debug` 时实际文件永远打不开（`--debug` 被当成路径先 open，失败后 break）。
**修复**：`main.cpp` 打开文件的参数循环里排除 `--debug`。

**验证**：全量重建；RingBuffer/PacketQueue/FrameQueue/Clock 单测全过；test_long_1080p / test_rot90 / test_h264 / test_wav 四个样例真实开播 8 秒无错误。

## 16. 音视频同步专项（第八轮实战）

### 坑 Z：主时钟数了"已写帧数"而不是"可听位置"
**现象**：画面稳定比声音快约 0.1~0.2s。
**根因**：`played_frames_` 统计的是写入声卡缓冲的帧数，而设备缓冲里还有最多 0.2s 的数据没被听到；`master_clock = 已写帧数 × 倍率` 因此一直领先实际声音一个缓冲深度。
**修复**：`get_played_seconds()` 改为"已写帧数 − `GetCurrentPadding()`"（声卡真实消费位置）；`IAudioClock` 仍作交叉校验，偏差过大回退帧计数。
**教训**：计数时钟要数"消费者位置"，不能数"生产者位置"。

### 坑 AA：seek 后设备缓冲里的旧音频继续播放
**现象**：每次 seek 后音画偏移约一个设备缓冲（0.2s），且持续存在。
**根因**：seek 只清了环形缓冲；WASAPI 设备缓冲里 seek 前的数据会继续播完，主时钟却已跳到目标点。
**修复**：新增 `AudioOutput::reset_stream()`——Stop → Reset → 帧计数归零 → 换新环形缓冲 → Start（暂停时保持停止），在 `sync_.seek()` 之前调用。

### 坑 AB：video_delay 把内容秒当墙钟秒
**现象**：变速（≠1x）时画面节奏错误：2x 偏慢（靠丢帧追）、0.5x 偏快。
**根因**：`video_delay` 返回帧间隔（内容秒）直接当 sleep 秒数；2x 时应等 0.033/2=0.0165s 而不是 0.033s。
**修复**：等待时间 = 内容时间差 ÷ 倍率（偏差微调同样换算成墙钟）。

### 坑 AC：pause/resume 与回调线程并发调 IAudioClient
**现象**：快速暂停/恢复偶发爆音、时钟跳动。
**根因**：`IAudioClient::Stop/Start` 与回调线程的 `GetBuffer/ReleaseBuffer` 无同步。
**修复**：新增 `client_mutex_` 串行化所有 IAudioClient 调用；暂停时回调线程跳过写入（帧计数天然冻结）。

**验证**：全量重建；单测全过；test_long_1080p / test_rot90 / test_h264 / test_wav 真实开播 8 秒无错误；本机 IAudioClock 不可靠时自动回退"可听位置帧计数"。

## 17. 播放中重开文件卡死（第九轮实战）

### 坑 AD：abort 是一次性的，open() 复用队列时没有复位
**现象**：播放过程中直接拖入另一个视频，画面卡在上一段最后一帧，声音消失；日志显示第二次"播放开始"后音/视频解码线程立刻"结束"。
**根因**：`close()` 用 `PacketQueue/FrameQueue::abort()` 唤醒阻塞线程，abort 会把 `aborted_` **永久置位**；而 `open()` 复用同一个 MediaPlayer 的成员队列，没有清除终止态。新会话的解码线程一 `pop()` 就命中 `aborted_`，立即退出——所以 close 的 join 不再卡死（上一轮已修），但新会话其实是"空的"。
**修复**：
1. `PacketQueue/FrameQueue` 新增 `reset()`：清除 `aborted_` 与内容并 notify；
2. `open()` 在 `close()` 之后调用 `video_packets_.reset(); audio_packets_.reset(); video_frames_.reset();`；
3. 新增单测：abort → pop 返回 nullptr → reset → 重新 push/pop 正常。
**验证**：给播放器加了 `--reopen <秒>` 回归入口（N 秒后重开同一文件）；修复前重开后 0 帧上屏（DRAW=0），修复后重开 10 秒内绘制 289 帧，音/视频解码线程持续存活。
**教训**："终止"和"复用"是两种状态，退出协议只保证 join 不卡死，不等于对象可以原样复用；任何一次性状态（abort、seek 代数、done 标志）都要在会话边界显式复位。

## 18. 音频快/慢与失音（第十轮实战）

### 坑 AE：换设备/变速后重采样器没有立即按新目标采样率重开
**现象**：切换扬声器或变速后，音频短暂变快/变慢（旧速率样本被新设备按错误速率消费）。
**根因**：重采样器目标采样率 = 设备采样率 ÷ 倍率；设备切换后旧重采样器仍在产出旧速率的样本，只有等解码线程的"兜底 rate 检查"（依赖循环时机）才重开，窗口期内听感变速。
**修复**：新增 `audio_resampler_reopen_` 请求标志；`set_speed()` 与 `set_audio_device()` 都会置位，音频解码线程循环顶部立即重开重采样器并清环形缓冲。

### 坑 AF：切换设备失败后旧设备已释放，没有兜底 → 永久无声
**根因**：`switch_device()` 失败时旧 client 已释放，直接返回错误；播放继续但没有任何音频设备。
**修复**：`set_audio_device()` 失败后自动回退到默认设备（`init` + `start`），仍失败才返回错误并记录日志。

### 坑 AG：seek 重置设备流失败被忽略 → 无声
**根因**：`reset_stream()`（Stop→Reset→Start）的 Start 失败只返回错误，`seek()` 忽略返回值，设备停在停止态。
**修复**：Start 失败重试一次（虚拟/蓝牙设备 Reset 后瞬时失败常见）；`seek()` 检查返回值并记 ERROR。

### 坑 AH：暂停状态跨会话残留 → 新文件无声
**根因**：`paused_` 是 AudioOutput 成员；暂停时拖入新文件，close→open 后新会话回调线程看到 `paused_` 仍为 true，永远跳过写入。
**修复**：`release_audio_objects()` 清除 `paused_`（新会话默认播放态）。

### 坑 AI：设备瞬时失效时回调空转且永远静音
**根因**：`GetBuffer` 连续失败时 run_loop 只 continue，无退避、无恢复。
**修复**：失败路径休眠 30ms 防空转，连续失败 30 次自动 `reset_stream()` 自愈并记 WARN。

**验证**：单测全过；4 样例真实播放回归通过；`--reopen` 重开回归通过（重开后 232 帧上屏，音频线程存活）。

## 19. seek 后音画对齐与快速来回拖动（第十一轮实战）

### 坑 AJ：seek 后"静音窗口"让主时钟提前走，产生恒定偏移
**现象**：每次 seek 后画面先动、声音晚到，且偏移不消失。
**根因**：seek 时主时钟已跳到目标点，但音频解码线程还要 flush + 重开重采样器 + 找关键帧（几十~几百 ms）；这段窗口里设备在播静音，主时钟随静音前进，音频内容却还没开始——偏移一旦形成就是恒定的，不会自愈。
**修复**：`freeze_until_audio(target, gen)` 把主时钟冻结在目标点，直到第一帧新音频写入设备缓冲；写入时按"写入位置"锚定（`audio_resume(pts, gen)`），使该帧到达声卡那一刻主时钟恰好等于它的 pts。

### 坑 AK：快速来回拖动时，旧 seek 的帧抢先锚定新 seek
**现象**：--seek 回归里三次快速跳转只有一次锚定，且锚定值对不上最新目标。
**根因**：单布尔 flush 标志会被多次 seek 折叠；旧 seek 的解码帧可能在新 seek 冻结之后写入并锚定。
**修复**：冻结/锚定绑定 seek 代数（generation）；只有"代数匹配的帧"能锚定，旧代数帧即使写入也不生效。

### 坑 AL：解封装推包跨过 seek flush，旧包混入新队列
**现象**：seek 到 20s 却锚定到 26.6s（旧读位置的数据）。
**根因**：解封装线程可能在 seek 清空队列时正阻塞在 push 上，flush 之后它把 seek 前读的旧包推入新队列；旧包在解码端被当成新数据。
**修复**：`PacketQueue` 给每个包记录**入队时的 seek 代数**（push 带 gen、pop 可带出 gen）；音频线程解码前检查"包代数 == 当前代数"，不匹配直接丢帧。

### 坑 AM：队列清空时代数记录不同步
**现象**：abort/reset 清了包队列但没清代数队列，新旧包代数错位，旧包混过检查（脚本插入 bug 的真实案例）。
**修复**：flush/abort/reset 三处都必须同步清空 `gens_`；已在单测外增加回归场景（abort→reset→push/pop 代数正确）。

**验证**：新增 `--seek <秒>` 回归入口（2 秒后自动连跳 target → 0.6×target → 0.8×target，间隔 400ms，模拟来回拖进度条）。修复前：三次 seek 只有一次锚定、锚定值错（26.6s）；修复后：三次 seek 三次锚定，first_pts 分别为 20.0 / 8.27 / 8.27，均等于各自关键帧落点，绘制持续不断。
**注意**：向后 seek 会落在目标前最近的关键帧（如目标 16s、关键帧 8.3s），音频从 8.3s 起播、画面从 8.3s 播到 16s——这是 FFmpeg BACKWARD seek 的固有行为，音画是同步的；若要"精确跳到目标"，需要 EXACT seek + 解码丢帧，属于后续优化项。
